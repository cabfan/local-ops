# 需求二 · 登录页 方案

- 版本：v1（修订 1）
- 日期：2026-08-29
- 状态：待评审
- 优先级：**P1（第二个落地）**
- 修订说明：数据层决策改为 **统一 SQLite**（P1 登录与 P2 GitLab 审查共用 `data/console.db`，标准库 `sqlite3`，仍零依赖）。

---

## 1. 背景与动机

当前「总控台」的访问控制依赖三类粗粒度手段：
1. 默认仅绑定本机回环（`CONSOLE_HOST=127.0.0.1`）；
2. 局域网访问通过 `CONSOLE_LAN_ALLOW` **IP 白名单**（环境变量）放行；
3. 写接口另有一把进程级随机 `console_session` cookie 用于防跨站请求 / 明文本地客户端。

痛点：**纯 IP 白名单授权不灵活** —— 公司内动态 IP、VPN 换地址、同事临时访问都会频繁失效而需要改环境变量重启；也没有「谁」的概念，无法对使用者做身份级授权。因此希望新增一个**登录页**，用口令/账号登录后取得会话权限，让局域网授权更友好可控。

## 2. 现状分析（认证现状）

- 入口：每个请求经 `Handler.authorize_request`（[server.py](file:///d:/00-code/local-ops/server.py#L3771)），只做 **Host 校验**（非当前控制台 Host → 421，[deny](file:///d:/00-code/local-ops/server.py#L3781)）+ **写接口**的会话 cookie 校验。
- IP 白名单：`CONSOLE_LAN_ALLOW` → `_ip_in_lan_allow`（[server.py](file:///d:/00-code/local-ops/server.py#L146)），纯 IP/CIDR 匹配。
- 已有会话机制但不是「登录」：`control_token = secrets.token_urlsafe(32)`（[server.py](file:///d:/00-code/local-ops/server.py#L3640)），通过 `console_session` cookie 下发（[L3746](file:///d:/00-code/local-ops/server.py#L3746)）。它本质是**本进程随机免登录凭证**（满足 `SameSite=Strict; HttpOnly`），并非用户口令，无法认证「人」。
- 前端已具备完整主题与页面结构，可承载登录视图；新增一个登录视图成本低。

## 3. 目标交互

- 访问总控台（尤其通过局域网打开）时，若未登录 → 显示一个**登录页**（口令输入），登录成功后进入控制台主界面。
- 登录后会话保持（cookie 会话 / 可配置可选的「记住我」）。
- 局域网授权从此不再依赖频繁改 `CONSOLE_LAN_ALLOW`，可用口令授权。
- 默认策略保持安全：本机回环访问可沿用免登录（`localhost`/`127.0.0.1`），**非回环一律要求登录**；`CONSOLE_LAN_ALLOW` 仍可继续为用户提供「免登录白名单」叠加选项。

## 4. 方案设计

### 4.1 认证模型
- 引入**管理账号**（默认单管理员，SQLite 账号表支持扩展多用户）：
  - 首次启动或未配置时，在设置页/首次运行时引导创建；
  - 存储：账号 + 口令哈希统一写入 `data/console.db` 的 `accounts` 表（标准库 `sqlite3`，`0600`）；`CONSOLE_PASSWORD` 环境变量可作为后端覆盖（优先环境变量，便于种子初始化/不落地磁盘）。口令存 `hashlib.scrypt` 哈希而非明文（标准库）。
- 登录成功 → 服务端签发**会话 token**，写入 `console_session` cookie（沿用现有 cookie 通道，`HttpOnly; SameSite=Strict; Path=/`），登录态与现有 `control_token` 区分开：一个是「本人登录凭证」，一个是「进程防跨站凭证」。会话 token 与过期时间登记在 `sessions` 表，便于吊销与「记住我」持久化。

### 4.2 接入点
- 在 `authorize_request` 增加登录判定分支：
  - 请求 `Host` 为回环（`127.0.0.1`/`::1`/`localhost`）且未开启强制登录 → 免登录（默认）；
  - 非回环 或 开启强制登录 → 校验登录会话 cookie；无/失效 → 未登录响应（前端跳登录页），不返回任何业务数据；
  - 登录页、静态资源、`/api/health` 等放行。
- 新增接口：
  - `POST /api/auth/login`：校验口令，成功签发会话 cookie `console_session=...`；
  - `POST /api/auth/logout`：清空会话；
  - `GET /api/auth/status`：返回当前是否已登录（供首屏判断）。
- 会话有效期：默认进程存活期，可选「记住我」延长（写带 N 天有效期的 token）；会话失效后回到登录页。

### 4.3 前端
- 新增「登录视图」`#view-login` + 顶栏/导航逻辑：检测到未登录态时重定向至登录页；登录页复用现有表单样式与主题，零 emoji。
- 首屏：`/api/auth/status` 判定 → 未登录先渲染登录页，登录成功后再拉 `/api/state` 进入主界面。

### 4.4 兼容与安全
- 保留 `CONSOLE_LAN_ALLOW` 作为可选白名单（命中即免登录），两者叠加，满足不同网络策略。
- 登录接口做**失败次数限制**（防爆破）、`scrypt` 口令哈希比较（恒定时间）。
- 沿用既有护栏：Host 421、回环默认免登录不降低本机体验、不把登录态透出到不被信任网络。
- 不引入第三方依赖（全程标准库：`sqlite3`、`hashlib.scrypt`、`hmac`、`time`）。数据库访问走单线程化的 `sqlite3`（连接复用 + 写锁），沿用配置写入的线程安全习惯。

## 5. 决策点

1. **回环是否免登录**：默认是（保持本机双击即用的体感）；是否提供「强制登录」开关（连本机也要求）。
2. **口令 + 用户名，还是纯口令**：单机场景建议**纯口令 PSK**，登录页只填口令，最简单；如需「谁能登录」再加用户名/账号映射。
3. **口令存储位置**：统一 `data/console.db` 的 `accounts` 表（推荐，支持多管理员）；`CONSOLE_PASSWORD` 环境变量作种子/覆盖是否保留。
4. **是否保留 `CONSOLE_LAN_ALLOW` 免登录白名单**：保留（叠加）还是彻底改为「一律口令登录」。

## 6. 验收标准

- 本机回环访问：默认免登录，直接进入控制台（若未开强制登录）。
- 局域网访问（或开启强制登录）：未登录弹登录页；口令错误提示、连续失败有冷却；输入正确口令后进入主界面，业务接口可用。
- 登出后再次访问回到登录页；关闭浏览器重开会话按配置失效。
- `make check` 全绿；补相关的认证后端测试。

## 7. 风险与影响面

- 改动集中在认证分支与前端视图中枢，后端为**增量分支**，风险中等。
- 关键：回环默认免登录必须保住，避免破坏「双击即用」的本机体感；局域网登录打通后，`CONSOLE_LAN_ALLOW` 语义变化需在 README / `RELEASE_CHECKLIST` 安全项中同步更新。
