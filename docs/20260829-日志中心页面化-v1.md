# 需求一 · 日志中心独立成页面视图 方案

- 版本：v1
- 日期：2026-08-29
- 状态：待评审
- 优先级：**P0（第一个落地）**

---

## 1. 背景与动机

「日志中心」当前不是独立页面，而是**两级弹层叠加**的结果：点击左侧导航轨「日志中心」弹出应用列表框，点某一应用后先关掉框、再弹出右侧日志抽屉，点抽屉遮罩任意处才关闭。想切换查看另一个应用的日志，必须重复「菜单 → 弹框 → 点应用 → 抽屉 → 关遮罩」整轮操作，缺少一个可停留、可连续切换的上下文，日常查多应用日志很不顺手。

本需求把「日志中心」改造为一个**常驻的第三个页面视图**，左右分栏，左侧应用列表、右侧日志详情，点击一次即可在任意应用间切换。

## 2. 现状分析

### 2.1 入口与结构
- 左侧导航轨 `rail-logs` 是 `data-action="logs"`（[index.html](file:///d:/00-code/local-ops/static/index.html#L38)），走**动作**而非**视图**；真正承接视图切换的只有 `data-view="launchpad"` / `data-view="services"` 两条 rail，对应 `#view-launchpad` / `#view-services` 两个 `section.view`。
- 日志中心的载体是 `#logsMask`（modal 弹框，应用列表）+ `#logDrawer`（抽屉，日志详情）两套弹层 DOM（[index.html](file:///d:/00-code/local-ops/static/index.html#L573)、[L619](file:///d:/00-code/local-ops/static/index.html#L619)）。

### 2.2 前端流程
- `widgets.js` `openLogsCenter()`：渲染 `renderLogsList()`（应用列表，运行中优先，底部固定「总控台日志」）后弹出 `#logsMask`（[widgets.js](file:///d:/00-code/local-ops/static/js/widgets.js#L402)）。
- 点击某行的 `logsRow` click：`closeLogsCenter(); openLogs(app)`（[widgets.js](file:///d:/00-code/local-ops/static/js/widgets.js#L366)）。
- `overlays.js` `openLogDrawer()`：定时器轮询日志，点遮罩 `closeLogs()` 关闭（[overlays.js](file:///d:/00-code/local-ops/static/js/overlays.js#L674)、[fetchLogs](file:///d:/00-code/local-ops/static/js/overlays.js#L687)）。

### 2.3 后端能力（已就绪，无需改动）
- `GET /api/apps/{id}/logs?tail=N` → `{"text":"..."}`（[handle_logs](file:///d:/00-code/local-ops/server.py#L3978)）
- `GET /api/console/log?tail=N`（总控台自身日志）
- 前端侧增量追加 + 1.5s 轮询 + `visibilitychange` 挂起/续拉的逻辑已封装好，可整体复用。

## 3. 目标交互

```
┌─────────────┬──────────────────────────────┐
│ 左侧列表      │ 右侧日志详情                  │
│ ──────────── │ ──────────────────────────── │
│ 🔍 搜索过滤   │ <应用名> · 日志        [刷新] │
│ [运行中]      │ ┌────────────────────────┐   │
│ [应用 A] ◄─   │ │ 日志文本（自动滚动）     │   │
│ [应用 B]      │ │                         │   │
│ [应用 C]      │ └────────────────────────┘   │
│ ──────────── │                               │
│ [总控台日志]   │                               │
└─────────────┴──────────────────────────────┘
```

- 左侧为应用列表，点击即在**同一视图内**切换右侧详情，全程不出现任何弹框/抽屉。
- 默认选中最近查看或运行的第一个应用；左侧保持「运行中优先」并新增加关键字搜索过滤；底部固定「总控台日志」。
- 右侧复用现有轮询端点；切到其它视图暂停轮询，切回自动续拉且保持滚动位置样较好。
- 空状态沿用现有文案。

## 4. 方案设计与改动清单

### 4.1 改动范围
| 文件 | 改动 |
|---|---|
| `static/index.html` | ① 新加一条 `rail-btn[data-view="logs"]`；把 `rail-logs` 由 `data-action="logs"` 改为 `data-view="logs"`；② 新增 `<section class="view" id="view-logs">` 左右分栏骨架；③ 移除/停用 `#logsMask`、`#logDrawer` 两套弹层 DOM |
| `static/app.js` | 把 `logs` 并入 `switchView` / `applyView` 的视图切换；视图进入时触发列表渲染与首屏拉取，离开时暂停轮询 |
| `static/js/widgets.js` | `renderLogsList` / `logsRow` 迁为「视图内列表」渲染（新增搜索过滤、选中态）；`openLogsCenter` 改为「切到 logs 视图」；`closeLogsCenter` 保留语义（切回上一视图） |
| `static/js/overlays.js` | 移除 `logDrawer`/`drawerMask` 弹层，仅保留 `fetchLogs` 增量拉取与轮询调度，宿主改指向视图右侧面板 |
| `static/js/core.js` | 主题/浮层注册表里移除 `#logDrawer`（如被列在 trap 层名单） |

### 4.2 关键实现点
- **轮询逻辑零改动**：`fetchLogs` 的 AppId/seq/增量追加/滚动定位/挂起逻辑原样保留，仅把挂载节点从 `logPre`（抽屉内）换成视图右侧 `<pre>`。
- **切视图暂停**：复用现有 `visibilitychange` 语义 —— 离开 `logs` 视图 = 隐藏 = 暂停；回到 `logs` = 可见 = 续拉。
- **选中记忆（可选）**：用 `localStorage` 记住最后看的 appId，下次进视图直接定位。
- 遵循项目约定：DOM 按 key 原地更新不整列表重绘、UI 零 emoji、动效遵守 `prefers-reduced-motion`、单一主题 `ops`。

## 5. 决策点

1. **旧弹层是否彻底删除**：建议整体移除两套弹层，避免新旧两套并存的逻辑分叉。
2. **选中记忆**：记忆上次 appId 到 `localStorage`（推荐），否则默认首个运行中应用。
3. **快捷键 ⌘J**：继续指向新视图（`switchView('logs')`）。
4. 是否需要在视图标题栏增加「暂停/滚动」切换（低优先级，可后置）。

## 6. 验收标准

- 从任一视图点击导航「日志中心」进入 logs 视图，左右分栏正常渲染。
- 连续点击多个应用，右侧日志即时切换续拉，无需关闭任何弹层。
- 日志随 1.5s 轮询增量追加，滚动定位正确；离开视图暂停、返回续拉。
- 「总控台日志」入口正常；空状态文案正确。
- `make check` 全部通过（前端语法、资源引用、测试；必要时补充前端纯函数测试）。

## 7. 风险与影响面

- 改动集中在**前端**，后端零改动，风险低。
- 注意移除弹层时同步更新 `core.js` 的浮层陷阱层名单，避免残留 `aria`/`inert` 状态异常。
